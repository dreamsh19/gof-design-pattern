- Structural Pattern
	- 클래스와 객체를 어떻게 조합하여 더 큰 구조를 만들지에 대한 패턴.
- Structural class pattern
	- 상속을 통해 인터페이스 또는 구현을 조합한다.
	- 예시1 : 다중 상속을 통해 서로 독립적인 클래스들의 기능을 합친다.
	- 예시2 : Adapter(클래스)
		- 서로다른 인터페이스에 대해 동일한 레벨의 추상화를 제공
		- private 상속을 통해 구현
- Structural object pattern
	- 객체를 조합하여 새로운 기능을 구현한다.
	- 객체 조합의 유연함은 런타임에 조합을 변경할 수 있다는 점에서 온다.
	- Composite
		- primitive 객체와 composite 객체 두 가지 종류를 조합하여 복잡한 구조를 만든다.
	- Proxy
		- 객체의 특정 프로퍼티에 대해서 한 단계의 우회 계층을 추가한다.
		- 이를 통해, 이 프로퍼티를 제한하거나, 확장하거나, 대체할 수 있게한다.
	- Flywieght
		- 객체의 공유(를 통한 공간 효율성에 집중한다)
		- 공유를 위한 전제는 객체에 상태가 없어야한다. (stateless)
		- 부가정보는 상태로서가 아니라 수행될때 전달되어야한다.
	- Facade
		- 단일 객체가 전체 하위시스템을 대표하도록 한다.
		- 하위 객체 집합들에 대한 게이트웨이 역할
			- 메시지를 적절한 하위시스템으로 포워딩하는 역할
	- Bridge
		- 추상화를 구현으로부터 분리한다.
	- Decorator
		- 내부에 객체를 감싸서 원래 메시지를 내부 객체에 포워딩하고,
		- 포워딩 전후에 작업을 추가한다.
